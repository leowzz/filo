# 批量与文件夹操作

通过 Cmd/Ctrl 点击、Shift 连选、框选或 Cmd/Ctrl+A 多选，在工具栏或右键菜单选择复制、移动或删除。右键和省略号菜单保留已有多选；打开、显示简介和重命名仅对单选开放。文件与文件夹可以混合选择。

## 行为

- 批量复制、移动保留各项原名称，每个顶层项目对应一条持久化传输任务。单选可以修改目标名称。提交失败逐项展示，再次提交只处理未开始项；任务执行失败在传输页查看。
- 文件夹复制包含所有子文件夹、隐藏文件及空目录，支持本地、S3 和跨连接传输。文件夹通过连接本地位置后复制或移动，原生上传/下载选择器用于文件。
- 文件夹移动先完成所有文件的大小与 SHA-256 校验及发布，再复核源目录成员、文件状态和目标内容，最后清理源位置。清理阶段开始后不再取消。远程文件夹重命名使用相同流程，并保存任务记录；本地重命名使用防覆盖的原生重命名。
- 不覆盖文件，也不合并已有同名文件夹。拒绝把文件夹放入自身或后代目录，包括连接了同一本地目录的不同子路径、同 S3 Endpoint/Bucket 下不同 Prefix 的情况。
- 普通删除优先系统回收站。永久删除明确提示将删除文件夹内全部内容，前端显式传入 `recursive: true`。未传递该参数的旧命令仍只允许删除空目录。
- 每项独立报告成功或失败；失败时刷新列表并显示剩余项目。回收站不可用只对对应失败项提供「改为永久删除」，点击后仍需再次确认。权限或路径错误不会自动转成永久删除。

## 边界

递归修改先完整扫描，遇到符号链接、特殊设备文件、不支持的名称或重复路径即停止，避免静默漏文件。最多扫描十万项，超过需分批。隐藏文件不受浏览器隐藏开关影响。

批量操作及文件夹操作不提供事务回滚。文件夹失败或取消时，已创建的目标目录和已发布文件保留，错误会说明；清理源目录失败可能留下部分源文件，错误会注明目标已保存。不要直接重复提交到同名目标，可检查后换用新名称。永久删除途中失败时已删除的内容无法恢复，只能处理剩余内容。

源扫描与删除、S3 Prefix 创建与其他客户端操作之间没有跨请求事务。不会递归删除扫描后新出现的文件；并发修改可导致操作失败。无需保留的本任务临时文件沿用已有清理机制。当前不保留完整 ACL、扩展属性、S3 标签及原修改时间，不支持断点续传。

## 验证入口

- `make check`、`make test`：类型、lint、Rust 格式与 Clippy；真实临时目录覆盖嵌套/隐藏/空目录、冲突、取消、只读/根目录保护、重叠连接、源成员变化、已发布目标被修改及递归删除。
- `FILO_S3_TEST_CONFIG="$HOME/.config/filo/rustfs.json" cargo test -p storage-application --test s3_integration -- --ignored --nocapture`：随机隔离 Prefix 下的本地→S3→本地文件夹往返、S3 重命名、跨 S3 移动及递归删除。
- 启动 `pnpm dev:web` 后运行 `ego-browser nodejs < scripts/test-batch-operations.mjs`：使用模拟 IPC 验证多选菜单、批量操作、失败重试去重、递归删除确认、混合结果和回收站失败后的再次确认，不修改真实文件。
