# S3 与本机 RustFS

当前支持 LocalFS + S3 Compatible。RustFS 是本机验收服务，不需要另起 Filo 后端服务器。

## 已实现

- 添加、测试、编辑和移除 S3 连接；Endpoint、Region、Path Style、Bucket、Prefix、只读访问及可选 Session Token。
- 系统凭据库保存完整凭据，SQLite 仅保存随机 credential_ref 和非敏感配置。macOS 将所有 S3 连接的凭据合并到同一个钥匙串条目，首次成功解锁后，同一进程内切换其他连接或并发传输共用这次读取；各连接仍使用自己的访问密钥和 Session Token。Windows/Linux 保持独立系统凭据条目。同一进程内缓存成功解锁的凭据，保存和删除同步更新缓存，失败读取可重试。编辑可保留凭据或替换；保存失败保留旧连接。测试连接不保存新填写的凭据，也不依赖 ListBuckets 权限。
- Bucket/Prefix 浏览、对象大小及修改时间、零字节目录标记、批量对象及非空 Prefix 永久删除。
- 文件与 Prefix 重命名：Copy → 校验 → Delete；目标已存在时拒绝。Prefix 按文件夹递归处理。
- Local → S3、S3 → Local、S3 → S3 文件及文件夹复制与移动；内容完整性校验、任务进度、取消和 SQLite 任务记录。本地目标使用 SHA-256；S3 上传通过 provider 返回的 ETag 比较普通 MD5 或按实际分片边界计算的组合 MD5。
- S3 浏览工具栏的上传/下载按钮调用原生文件选择器。临时授权只限选中文件，任务结束后撤销，不添加新的本地位置；前端不能提交任意本地路径。
- 多个连接可以使用相同 Bucket/Prefix 名称；迁移保留原本地目录唯一性及已有连接。

S3 上传先写唯一临时对象，使用 HEAD 获取 provider 的 ETag 与本地增量计算的校验值及大小比较，再以条件服务端复制发布，最后 HEAD 校验目标；整个上传校验过程不发起内容 GET，不占下载限速。普通对象比较完整 MD5，分片对象比较固定 8 MiB 分片的组合 MD5，不能把分片 ETag 直接当完整文件 MD5。缺失或不可比较的 ETag（例如不支持此语义的加密对象）会明确失败并保留源文件，不自动退回下载校验，不将自定义元数据当服务端校验值。新建使用 `If-None-Match: *`，覆盖使用目标 `If-Match`；大于 5 GiB 的发布使用服务端 UploadPartCopy。兼容服务必须支持条件写入，不自动退回无条件覆盖。S3 原地重命名和目录移动的最终安全复核仍沿用现有流程。

## macOS 凭据解锁与旧数据迁移

共用条目使用服务名 `dev.filo.desktop.s3`、账户名 `vault-v1`，内部按随机 `credential_ref` 保存各连接凭据。首次访问读取整个条目，后续访问复用内存缓存；删除一个连接不会删除其他连接的凭据，删完最后一个连接仍保留空条目及其授权记录。多个应用进程通过 `~/Library/Application Support/dev.filo.desktop/credentials.lock` 协调读写；该文件只包含随机版本号，不含密钥或连接信息。

已有的逐连接条目在首次访问时迁移：读取旧凭据、成功写入共用条目后才清理旧条目。旧条目有各自的系统访问权限，因此首次迁移仍可能逐条要求授权；拒绝授权、读取损坏数据或写入失败不会覆盖原有凭据。清理失败保留旧副本，移除连接时会重试清理。迁移完成后，授权次数不再随连接数量增加。

这不改变开发签名方案：自签应用重新编译后，代码哈希变化仍可能触发共用条目的一次系统授权。签名身份稳定的回归测试不等于跨重编译免钥匙串授权。钥匙串锁定等系统状态也可能要求重新授权。

## 添加存储与提供商表单

添加弹窗先显示本地文件系统，再显示 S3 存储的四个入口。选择提供商后，同一弹窗带动画向右展开表单，左侧入口保持可见并高亮当前选择。可直接切换提供商或返回选择，当前弹窗内各提供商的草稿分别保留；关闭弹窗后清除。窄窗口下表单在选择区下方展开。测试或保存期间锁定切换与关闭。

- **通用 S3 协议**：自定义 Endpoint、Region；Endpoint 留空使用 AWS S3；高级设置可切换 Path Style。
- **RustFS**：默认 API 地址 `http://127.0.0.1:9000`、Region `us-east-1`、Path Style。地域和寻址方式放在高级设置中，支持自建服务的非默认配置。
- **火山引擎 TOS**：提供地域列表，按地域生成 `tos-s3-{region}.volces.com` 公网地址或 `tos-s3-{region}.ivolces.com` 内网地址，默认虚拟主机式访问。
- **阿里云 OSS**：提供公共云地域列表，按地域生成 `s3.oss-{region}.aliyuncs.com` 公网地址或 `s3.oss-{region}-internal.aliyuncs.com` 内网地址，默认虚拟主机式访问。

云服务支持手动填写其他地域与自定义 S3 服务地址；地址不含 Bucket 或对象路径。所有提供商均可指定目录前缀、只读访问及临时凭据 Token。连接配置保存提供商类型，编辑时恢复对应表单；旧配置仍使用通用表单，保留原有参数与凭据。

地域与地址规则于 2026-09-16 核对：[RustFS](https://docs.rustfs.com/en/developer/sdk/python)、[TOS 地域和访问域名](https://www.volcengine.com/docs/6349/107356)、[OSS S3 接入](https://help.aliyun.com/zh/oss/developer-reference/use-aws-sdks-to-access-oss)、[OSS 地域列表](https://help.aliyun.com/zh/oss/user-guide/regions-and-endpoints)。地域选项为预置列表，不自动请求云账户。

表单交互回归：启动 Vite preview（端口 1422），执行 `ego-browser nodejs < scripts/test-s3-providers.mjs`。使用模拟 IPC 验证配置提交、保存与编辑，不访问真实云存储；TOS / OSS 的实际连接与完整文件操作仍需有效账户实测。

## 本机服务

用户指定的安装步骤：

```sh
brew tap rustfs/homebrew-tap
brew install rustfs
rustfs --version
```

2026-09-16：tap 已添加并仅信任 `rustfs/tap/rustfs` 公式。`brew install` 被本机缺少独立 Command Line Tools 阻止，因此安装了该公式指定的官方 macOS ARM64 预编译包到 `~/.local/bin/rustfs`，校验公式中的 SHA-256 一致。当前为 **1.0.0-rc.6**，未伪造 Homebrew 安装记录或修改系统开发工具配置。

- S3 API：`http://127.0.0.1:9000`
- 控制台：`http://127.0.0.1:9001/rustfs/console/`
- Region：`us-east-1`
- Bucket：`filo-demo`
- Path Style：启用
- 本机凭据文件：`~/.config/filo/rustfs.json`，权限 `600`，不进入仓库或输出日志。Filo 连接另存系统钥匙串。
- 数据、日志与 PID：`~/.local/share/filo-rustfs/`。

```sh
uv run scripts/rustfs-local.py start
uv run scripts/rustfs-local.py status
uv run scripts/rustfs-local.py stop
```

脚本生成随机初始密钥、只绑定回环地址、创建已有测试 Bucket 或复用健康服务。stop 保留数据；当前没有配置开机自启。控制台使用本机配置文件中的凭据登录。

## 验证

普通检查：

```sh
make check
make test
make dev
```

真实 S3 测试需要显式提供测试配置，默认忽略，避免普通单元测试访问外部存储：

```sh
FILO_S3_TEST_CONFIG="$HOME/.config/filo/rustfs.json" \
  cargo test -p storage-application --test s3_integration -- --ignored --nocapture
```

使用上述 JSON 字段连接测试 Bucket。测试在随机 `filo-tests/<uuid>` Prefix 下执行并清理自己的对象。覆盖 9 MiB 分段上传下载内容一致、空文件、S3 重命名、跨 S3 位置移动、原生选择文件传输服务、并发同名目标保护、只读与根目录保护、配置编辑/重启、凭据轮换以及数据库无明文密钥。离线测试另覆盖临时文件授权不允许访问兄弟文件，以及 Endpoint 和路径边界。

## 当前限制

- 没有暂停和断点续传；批量与递归操作见 [操作说明](12-batch-and-folders.md)。
- 目录已使用分页与虚拟列表；首次查询为全局排序/筛选需遍历当前层，见 [冲突处理与大目录](13-conflicts-and-paging.md)。
- 对象键必须符合 Filo 的可移植逻辑路径规则；包含 `..`、反斜杠、冒号或需要规范化才能访问的键不展示。同名文件与 Prefix 并存时拒绝操作，需在控制台整理。
- 文件夹复制/移动失败或取消时，已发布的目标内容保留，需要检查后重试。取消/失败会异步终止分段上传并删除本任务临时对象；服务不可达或强制退出可能遗留 `.filo-transfer-*` 对象/分段上传，需在控制台清理。中断任务不自动恢复。
- 同 Volume S3 移动及重命名进入复制/校验/删除提交阶段后不再取消。超过 5 GiB 的服务端分片复制路径已编译检查，尚未用超过 5 GiB 的实物测试。
- 校验或源删除失败会保留源文件；已经发布的目标可能仍存在。外部客户端在最终检查与删除之间改写源对象仍存在竞态，此版本不提供版本锁或跨请求事务。
- 上传与复制不保留全部对象 Metadata、Tags、ACL 或原修改时间；S3 版本、签名下载链接、Bucket 创建/空桶删除和对象属性管理已接入，见 [浏览与 S3 高级管理](14-browsing-and-s3-management.md)；IAM 管理仍不包含。
- 本轮实测 RustFS；AWS S3、MinIO、R2 等其他兼容服务及 Windows/Linux 尚未实机验收。

服务端口参考：[RustFS 官方状态检查文档](https://docs.rustfs.com/en/operations/status-check)。
